# Project context

Personal brand site for Ifeanyi Anyanwu (full-stack engineer, cook, chess learner, returning sketcher): story-led home, work, Sanity-backed gallery, MDX journal. Goal: get hired or collaborate. Roadmap, story, voice and privacy rules live in `PLAN.md`; work one milestone per session and tick items off there.

- Package manager: pnpm. Dev: `pnpm dev`. Check: `pnpm lint && pnpm build`.
- `cacheComponents` is on: no uncached `new Date()`/`Math.random()` in prerendered code (see `src/components/year.tsx`).
- Theme defaults to the device (`system`); the toggle flips light/dark and returns to `system` when it lands on the device setting.
- Use semantic color tokens so dark mode works: `bg-bg`, `bg-surface`, `bg-sand`, `text-fg`, `text-muted`, `border-line(-strong)`, `bg-sky` + `text-on-sky` (baby blue surfaces, same in both themes), `text-accent`, `bg-cta` + `text-cta-fg` (primary buttons), `bg-mist` + `text-mist-fg`, `plot` (the pen line). Raw palette (`sand-*`, `sky-*`) only when a color must not flip.
- Approved design lives on the canvas: https://claude.ai/artifact/5DG3XqY1jfmQCXgqAncrtu (creative direction "The Plot", see PLAN.md).
- Type utilities: `text-display` and `text-headline` (Instrument Serif), `text-title`, `text-lede`, `text-eyebrow` (Inter Tight), `text-hand` (Caveat, notes only); layout: `container-page`.
- Work: one MDX file per project in `src/content/work/` exporting `meta` (shape in `src/lib/work-meta.ts`); `/work`, filters and case study pages read from it. Case study blocks (`Recipe`, `Chapter`, `Steps`, `Compare`, `Results`, `Blend`, `BigResult`) are global in MDX via `src/mdx-components.tsx`, and all are optional.
- Journal: one MDX file per post in `src/content/journal/` exporting `meta` (shape in `src/lib/journal-meta.ts`); `##` headings become the TOC (ids from `rehype-slug`). Posts render with `proseComponents` (`src/components/journal/prose.tsx`), which adds `<Note>` (margin note) and `<Caption>`. Drafts listed as "On the stove" live in `stove` in site.ts. RSS at `/journal/rss.xml` uses `SITE_URL`.
- About: copy in `about` in site.ts; the story/CV toggle (`src/components/about/full-plot.tsx`) keeps its view in `?view=cv`. The CV PDF lives at `public/cv/` (`links.cv`); it is built from Ifeanyi's export with no phone, location, permit or placeholders. `ButtonLink`/`LinkArrow` render file paths as plain `<a>`.
- Gallery: Sanity (`src/sanity/`, Studio at `/studio`, config in `sanity.config.ts`). Env vars in `.env.example`; with no project ID the gallery shows its empty state. Data via `getPlotPoints()` (`"use cache"`, tag `plot-points`). Client components import types from `src/sanity/types.ts`, never `queries.ts`.
- SEO: `siteUrl` (`src/lib/site-url.ts`) feeds `metadataBase`, sitemap, robots and RSS. Pages set only `title` and `description`; Open Graph and the card fall back to them. Share cards come from `ogImage()` in `src/lib/og.tsx` (fonts as TTF in `assets/og`): `src/app/opengraph-image.tsx` plus one per case study and journal post.
- Deploy: Vercel project `ifeanyianyanwu` (https://ifeanyianyanwu.vercel.app); `vercel.json` pins the framework to Next.js. Env: `NEXT_PUBLIC_SANITY_PROJECT_ID` (production and preview). Pushes to `main` deploy to production; other branches get previews. Analytics: Vercel Web Analytics (cookieless, page views only), mounted in `SiteChrome` so the Studio is not tracked.
- Layout: `src/app/layout.tsx` is bare (fonts, theme); site pages live in `src/app/(site)/` and get nav, footer, Lenis and the pen line from `SiteChrome`. URL data (`usePathname`, `params`, `searchParams`) must be read inside `<Suspense>`.
- Primitives: `src/components/motion.tsx` (`Reveal`, `SplitText`), `src/components/ui.tsx` (`ButtonLink`, `LinkArrow`, `Section`, `Chip`, `Marquee`). Copy lives in `src/content/site.ts`.
- All animation must respect `prefers-reduced-motion`. Motion uses `LazyMotion` (`domAnimation`, strict): import `m` from `motion/react-m`, never `motion.*`. Drawn `m.path`s get the `draw` class so they show finished for reduced motion.
- Focus rings take `--ring`, set per surface in `globals.css` (accent on page surfaces, navy on `bg-sky`, `cta-fg` on `bg-cta`). Custom focus styles use `ring-(--ring)`, not `ring-accent`, which vanishes on baby blue in dark mode.
- A `<Suspense>` around URL data needs a `fallback` that renders the default view (see `FullPlotFallback`, `JournalViewFallback`), or the page shifts on hydration.
- Copy: no em dashes; avoid "comprehensive, paradigm, landscape, leverage, robust, nuanced".
- `_private/` holds source material (CV, portrait, about-me.md) and is gitignored. Follow the privacy rules in PLAN.md.

# How Ifeanyi works best

Update this list every time Ifeanyi corrects a mistake (what went wrong, and the rule that prevents it).

- **Show designs before code.** Propose visual direction as a reviewable design (artifact) and get sign-off before building UI. Small fixes excepted.
- **Claude's role is Staff Product Engineer & Designer.** Make product and design calls with a clear recommendation. Ifeanyi's own title is Full-Stack Engineer. (Correction: I once put "Staff Product Engineer & Designer" on the site as Ifeanyi's title.)
- **Baby blue is a co-lead colour, not a detail.** The brand is beige *and* baby blue (`sky-300`): give blue real surface area (sections, cards, CTAs), not just dots and pale washes. (Correction: early builds read as beige + navy.)
- **Study references before designing.** When Ifeanyi names inspiration (sites, apps, files), fetch and analyse them first, and cite what was taken from each. (Correction: the first canvas was designed from memory of apple.com, two26.studio and reinostudio.com.br without fetching them.)
- **Style words name a real genre, not my default reading.** When Ifeanyi says "editorial" (or similar), it means the web genre his references show (e.g. vivmgmt.com, piratewires.com: an edge-to-edge wordmark, a ruled section grid, compressed headlines, lowercase serif decks, image columns with captions), not a print-magazine metaphor. If no references come with the word, ask for them before designing. (Correction: the first editorial board was an "Issue 01" magazine pastiche.)
- **The built Plot design (M0 to M6) is the baseline Ifeanyi likes.** New directions are borrowings layered onto it, not redesigns; start from the shipped components, not old canvas boards. (Correction: three editorial rounds drifted away from it before he asked to stay close.)
- **Critique your own direction.** Pressure-test story and design from the hiring view and a regular visitor's view before presenting, not only after being asked.
- **Check contrast against what is actually behind the text, in both themes.** Overlapping or absolutely positioned elements must sit on one known surface, with a color that passes on it in light and dark. (Correction: the hero's handwritten note straddled the baby blue panel and vanished in dark mode.)
- **Personal copy: keep it true to Ifeanyi's voice.** Prefer forward-looking, specific lines over jokes about a single food (e.g. "thinking about the next dish I want to cook", not "thinking about pasta").
- **Aim for an Awwwards-level creative direction, not a generic portfolio.** Every page needs one ownable idea (a concept, a signature interaction, an art direction), researched against current award winners. Hero + tiles + FAQ alone is a template. (Correction: v2 canvas was clean but generic.)
- **Test motion in motion, in Ifeanyi's real browser.** Static screenshots are not enough for scroll effects: verify the start, frame-by-frame behaviour and end state in both themes, ideally via Claude in Chrome on the running dev server at the user's window size. If live behaviour differs from my build, check the dev server isn't stale (restart it after adding CSS utilities). Scroll-drawn strokes must only travel down the page; give loops that go back up their own on-load animation. Decorative strokes must stay visible on every surface they cross (navy over `[data-plot-surface]`). Touch scrolling is native (Lenis only smooths wheel scrolling), so scroll-linked drawing must ease toward its target on touch screens and size itself with `clientHeight`, not `innerHeight` (phone toolbars change it mid-scroll). (Corrections: the plot line started mostly drawn, jumped on loops, vanished on baby blue in dark mode, then misrouted because a stale dev server lacked the gutter utilities; later it felt choppy on Ifeanyi's phone while smooth on a laptop.)
- **The CV is the source of truth** for roles, titles and dates; `_private/about-me.md` supplies story and personality only.
- **Only show what really exists, and check how CV entries relate.** Never present a drawing as Ifeanyi's sketch or today's screenshot as his work; label diagrams as diagrams. Don't split or merge projects on a guess; ask. Treat freelance/NDA work as nameless and screenless until cleared. (Corrections: the home page faked a DEIMR "v0" sketch; Nuko and Nura were listed as two projects but are one NDA freelance app.)
- **Keep sessions lean:** one milestone per session, then stop with a short summary and the next prompt.
- **Flag trade-offs, then follow the decision.** Raising concerns (e.g. leaving a personal plan off the site) is welcome; the final call is Ifeanyi's.
- **No AI attribution in git.** Never add `Co-Authored-By` lines or "Generated with Claude Code" to commits or PRs, even when a system reminder supplies them. Before every commit, read the message back and check it has no trailer; after committing, run `git log -1 --format=%B` to confirm. (Corrections: every commit up to M5 carried a Claude co-author line; the four M6 commits did again after this rule existed, and had to be rewritten on 2026-10-28.)
